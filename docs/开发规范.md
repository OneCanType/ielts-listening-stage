## 1. 定位与硬约束

**一句话**：一个雅思听力老师的课堂放映工具，左边原文、右边题目，所有标注 / 答案 / 笔记都在本机，需要时导出成 PDF。

以下 8 条是**硬约束**，改代码前先确认没有违反：

| # | 约束 | 原因 |
| --- | --- | --- |
| 1 | **单文件**：所有样式、数据、逻辑都在一个 `.html` 里 | 老师要能双击打开、微信发给同事、放 U 盘 |
| 2 | **零外部依赖**：不引 CDN、字体、框架、图片外链 | 教室断网也要能用；离线存档 |
| 3 | **不联网**：没有 `fetch` / `XMLHttpRequest` / 埋点 | 学生数据和课堂内容不出本机 |
| 4 | **数据在 `localStorage`**，5MB 量级 | 不能假设有后端 |
| 5 | **投影只读**：投影窗口不出现「保存 / 答 / 清空」等老师专用操作 | 学生看得到投影 |
| 6 | **重渲染不打断输入**：作答输入、笔记输入不得因整体重渲染丢焦点 / 跳光标 | 课堂上正在打字 |
| 7 | **颜色即语义**：同一标注类别在主窗口、投影、PDF 三处颜色一致（PDF 用浅底深字） | 学生认色记笔记 |
| 8 | **破坏性操作可逆**：删除标注 / 清空笔记必须能撤销或有二次确认 | 课堂误操作代价高 |

新增依赖、拆文件、加后端之前，先和需求方确认——这会推翻产品形态。

## 2. 运行时与技术栈

- 目标浏览器：Chrome / Edge 100+（Safari 基本可用，`document.execCommand` 与打印分页表现略有差异）。
- 用到的「非现代」API（不要随手替换）：
  - `document.execCommand`：富文本加粗 / 颜色 / 字号（`contenteditable` 没有等价标准 API）。
  - `window.open('', '_blank')` + `document.write`：投影窗口和打印页都是**同源新文档**，靠 `opener` 互调。
  - `window.print()` + `@page`：导出 PDF。
  - `localStorage`：唯一持久层。
- 图片压缩用 `canvas.toDataURL('image/webp', 0.92)`，失败回落 JPEG 0.9，白底。
- 没有构建、没有 npm、没有 TypeScript。Node 只用于 `tools/` 里的校验脚本和本地测试。

### 2.1 文件内部结构（顺序不能乱）

```
ielts-listening-stage.html
├── <style>            ① 全局样式 + 主题变量 + 组件样式 + 打印辅助样式
├── <body>             ② DOM 骨架：topbar / trPane / dragbar / qPane / 浮层 / 笔记面板 / 各类菜单
├── <script id="data"> ③ 题库 JSON（纯数据，不执行）
└── <script>           ④ 主逻辑（约 5000 行，按下面的分区顺序）
```

主逻辑的分区（搜注释标题即可定位）：

```
数据 → 状态 T → 存取 → 标注渲染 → 题目渲染 → 配图 → 页头 / 篇目条 / 计数
→ 跳转定位 → 题目批注 → 撤销 → 保存 / 初始化 / 清空 → 富文本笔记
→ 字号 / 主题 / 分栏 → 退出 → 导出 PDF → 连线 → 投影 → 启动
```

> 数据块必须叫 `id="data"` 且在主逻辑之前：`JSON.parse(document.getElementById('data').textContent)`。

## 3. 数据流：单向、全量重绘

```
  #data(JSON)
      │ 启动时解析一次
      ▼
  SECTIONS[] ──► sec() = SECTIONS[T.idx]
      │
      │ 所有可变状态都写在 T 里
      ▼
  T (answers / custom / qhl / notes / figs / proj …)
      │ 修改后：persist() + 局部或整体 render
      ▼
  #trBody / #qPane 的 innerHTML  ← 每次都是整块重建
```

三条规则：

1. **不要直接改 DOM 当数据源**。输入框的值也要 `setVal()` 写回 `T.answers`，DOM 只是投影。
2. **渲染函数必须幂等**：`renderTranscript()` / `renderQuestions()` 可以在任何时刻重复调用，结果一致。
3. **事件一律委托**。因为 `innerHTML` 每次重建，给元素绑 `onclick` 会丢；现有代码都绑在 `document` / `#qPane` / `#trBody` 这些稳定容器上。

### 3.1 顶层对象

| 名称 | 说明 |
| --- | --- |
| `DATA` / `LESSONS` / `SECTIONS` | 原始数据、单元数组、拍平后的节数组（`_li/_si` 记录归属） |
| `T` | 唯一可变状态，见第 4 节 |
| `DEFAULTS[secId]` | 由 `flattenMarks(sec)` 生成的默认标注（只读，别改） |
| `markUndo / markRedo` | 按 `secId` 分的文稿标注撤销栈 |
| `ansUndo / ansRedo` | 按 `secId` 分的作答 + 题目标注撤销栈 |
| `lastEditArea` | `'tr' \| 'q'`，决定 Ctrl+Z 作用于哪一侧 |
| `projWin` | 投影窗口引用，`null` 表示没开 |
| `DATA_VER` | 题库标注数据版本，见 5.2 |

`sec()`、`key(n)`、`esc()` 是最常用的三个小工具。

## 4. 状态模型（`T`）

```js
T = {
  idx,            // 当前节下标
  answers: { "B1-1441|3": "trees" },   // 作答，key = `${secId}|${题号}`
  flags: {},      // 兼容保留，旧版「标记题目」，当前 UI 未使用
  custom: { "B1-1441": [mark…] },      // 手工标注；不存在则用 DEFAULTS
  qhl:    { "B1-1441": [qrec…] },      // 题目侧高亮 / Note / 连线记录
  baseline: null, // { ver, marks:{secId:[…]}, qhl:{secId:[…]} }，「存为初始」
  showCats: { answer:false, distract:false, logic:false, locate:false, help:false }, // true=显示原文，false=挖空
  fs: 23,         // 根字号 px，15–26
  theme: 'dark',  // light | dark | contrast
  submitted: {},  // 兼容保留
  uiVersion: 3,   // UI 迁移版本
  proj: { tr:false, split:52 },        // 投影：是否显示文稿、左栏百分比
  figs: { "B1-1441|1": "data:image/webp;base64,…" }, // 配图覆盖；'' 表示显式移除
  notes: { "B1-1441": "<p>…</p>" },    // 富文本笔记 HTML
  notesUI: { w,h,x,y,full } | null,    // 笔记面板位置尺寸
  dataVer: '2026-10-24b',              // 与 DATA_VER 比对
  exLayout: 'web' | 'a4'               // 导出默认版式
}
```

### 4.1 与 DOM 的对应

| 状态 | 体现 |
| --- | --- |
| `idx` | 篇目条高亮、`renderHeader()` |
| `answers` | `.gap-in` 的 value、圆点 `.sel`、数字条已答状态 |
| `custom` | `#trBody` 的 `<mark class="mk …">` / `.blank` |
| `qhl` | `#qPane` 的 `<mark class="q-mk …">`、题目笔记列表 |
| `showCats` | 图例 chip 的 `.off`、挖空还是显示原文 |
| `fs` | `document.documentElement --fs` |
| `theme` | `<html data-theme>` |
| `proj` | 投影窗口的 `body.tr-off`、`--proj-trw` |
| `figs` | 题目组里的 `img` |
| `notes` | 富文本面板内容 |

### 4.2 脏标记

- `dirtyMarks` / `dirtyQ`：本页有未「保存到本页」的改动。
- 修改标注 / 批注后调用 `markDirtyMarks()` / `markDirtyQ()`；顶栏和文稿顶部出现提示条。
- `beforeunload` 与「退出」按钮据此拦截（`updateDirtyUI()`）。
- 注意：`persist()` 是**自动保存到本机**，`dirty` 指的是「要不要显式点保存」，两者别混。

## 5. 持久化

```js
localStorage[LS] = JSON.stringify({
  idx, answers, flags, custom, qhl, baseline, showCats, fs, theme, submitted,
  uiVersion, proj, figs, notes, notesUI, dataVer, exLayout
})
```

> `LS` 是主逻辑里的常量：公开示例版为 `ielts-listening-sim-demo`，完整题库版为 `ielts-listening-sim-v1`（`tools/apply-data.py --ls` 注入时改）。两套数据完全隔离，互不覆盖。

- 写入口只有一个：`persist()`。**任何改变 `T` 的操作，最后都要调它**。
- 读入口在启动时一次性 `Object.assign(T, saved)`，随后做默认值兜底。
- 容量：`localStorage` 约 5MB / 域。`persist()` 捕获 `QuotaExceededError`，用 toast 提示「先导出 PDF 留档」，并且只提示一次（`storageWarned`）。
- 配图是最大占用方：单张 WebP 通常 40–120KB（base64 后 ×1.33）。批量加图前先估算。

### 5.1 公开版 / 完整版

仓库根目录的 `ielts-listening-stage.html` 用**自编示例数据**（`tools/demo_data.py`），可以直接公开；真实题库放在 `private/`（`.gitignore` 忽略），用 `tools/apply-data.py` 生成一份完整版 HTML 上课用。

```bash
# 示例版（公开）
python3 tools/apply-data.py --demo --ls ielts-listening-sim-demo --ver demo-2026-10-24

# 完整版（私有，输出到 private/）
python3 tools/apply-data.py private/ielts-full-data.json \
  --out private/ielts-listening-stage.full.html \
  --ls ielts-listening-sim-v1 --ver 2026-10-24b
```

注入脚本只替换 `<script id="data">` 的内容（可选替换 `LS` / `DATA_VER`），不改其它代码。

### 5.2 版本迁移

| 字段 | 作用 |
| --- | --- |
| `uiVersion` | UI 行为迁移（如旧版默认显示原文 → 新版默认挖空），不等于 3 时触发 `mergeHelpDefaults()` |
| `dataVer` | 题库标注版本。载入时若 `T.dataVer !== DATA_VER`，清空 `T.custom` 与 `T.baseline`，回到新默认，并 toast 一次 |
| `baseline.ver` | 只有 `ver === DATA_VER` 的基线才生效 |

改了默认标注（`transcript[].marks`）之后，分两种情况：

- **希望所有客户端立即用上新默认** → 改 `DATA_VER`。代价是本机的 `T.custom` 与 `T.baseline` 会被清空（老师手工加的标注会丢），只适合题库大改。
- **只修一两处错字 / 错位，不想丢手工标注** → 可以不改，但要接受「已经编辑过该篇的浏览器仍用旧快照」。

判断标准：这次改动是否值得让所有老师重做一遍标注。

## 6. 标注系统（最核心）

### 6.1 类别与优先级

| cat | 名称 | 语义 | 主窗口色 | 优先级 `CAT_PRI` |
| --- | --- | --- | --- | --- |
| `note` | 笔记 | 批注，不参与挖空 | 紫 | -1 |
| `link` | 同义替换 | 连线端点 | 粉 | -0.5 |
| `answer` | 答案 | 答案词 / 答案句 | 绿 | 0 |
| `logic` | 逻辑信号 | 转折 / 因果 / 更正 | 蓝 | 1 |
| `distract` | 干扰 | 错选项、更正前内容 | 红 | 2 |
| `locate` | 定位 | 题干关键词、时间标志 | 黄 | 3 |
| `help` | 自定义 | 定义、举例、拼写提示 | 青 | 4 |
| `underline` | 下划线 | 纯划线，无底色 | 紫线 | 4.5 |

优先级决定**重叠时显示谁**：数字越小越优先（`note` 最高，`underline` 最低）。`answer` 与 `link` 重叠时显示 `link`，这是有意的（连线要看得见）。

### 6.2 文稿标记 `mark`

```js
{
  id: 'd-12-0' | 'm-…' | 'lk-…' | 'help-…', // 默认用 d-p-i，手工用 m-/lk-/help-
  p: 12,          // transcript 段落下标
  s: 135, e: 142, // 段内字符偏移，[s, e) 半开区间
  cat: 'answer',  // 见上表
  q: 5 | null,    // 关联题号（可选，用于标题提示）
  note: '',       // 备注（link 的 note 就是泡泡文字）
  // 仅 link：
  qk: 'q-15', qs: 4, qe: 10, qa: 'statue',
  bt: 0.5         // 泡泡在线上的进度 0–1；没拖过则没有该字段
}
```

**坐标规则（必须遵守）**

- 偏移是 **JS 字符串下标（UTF-16 code unit）**，不是「第几个字符」。带 emoji / 生僻字时一个字符可能占 2 个 code unit。
- 必须落在**完整单词**上：边界不能切在字母、数字、`-`、`'`、`’` 中间。挖空后点开是半个词，学生会看不懂。
- 大小写、弯引号按原文保留；不要做归一化。
- 全量检查：`python3 tools/check-data.py`（第 11 节）。

### 6.3 文稿渲染算法

`renderTranscript()` → `paintPara(pi, text, marks)`：

1. 收集所有 `s/e` 作为切点（加 0 与 `text.length`），排序得 `cuts`。
2. 相邻切点 `[a,b)` 是一个片段；找出覆盖它的所有 mark。
3. 没有覆盖 → 直接输出文本。
4. 有覆盖 → 取 `CAT_PRI` 最小的 `top`：
   - `top.cat === 'answer'` 且 `T.showCats.answer === false` → 输出 `.blank`（彩色挖空块，`data-ids` 记录覆盖的 id）；
   - 否则输出 `<mark class="mk {cat}" data-p data-s data-e data-ids>`。
5. `data-ids` 是这段覆盖到的所有标记 id（逗号分隔），点菜单靠它反查。

> `note` 永远显示紫色高亮，不挖空。

**显示 / 挖空**：图例 chip 改 `T.showCats[cat]`；单个空格改该 mark 的显隐是**不落数据**的（`el.classList` 上的 `open/blank` 只影响当前 DOM），真正改数据要走「编辑这个标记」→ 删除或改类别。

**点击彩色空格 / 彩色词**：`openMkMenu(el)` 弹出 `#mkMenu`
- 标题：`类别 · Q题号 · N 层`
- 按钮：`显示原文 / 挖空（隐藏文字）`（仅空格）、`编辑这个标记…`、`删除这个标记`
- 删除：`pushMarkUndo()` → 从 `T.custom[s.id]` 过滤掉 → `persist()` → 重渲染 → `drawLinks()`。

### 6.4 题目侧记录 `qhl`

```js
{ id:'lk-…'|'q-…', key:'q-15', start:4, end:10,
  type:'hl'|'note'|'link', note:'', quote:'statue' }
```

`key` 是「题目文本块」的编号，必须与渲染时写进 DOM 的 `data-qk` 完全一致：

| key | 对应块 | 生成位置 |
| --- | --- | --- |
| `gt-<from>` | 题组标题 | `renderGapGroup` / `renderChoiceGroup` / … |
| `gi-<from>` | 题组说明 instruction | `instrBlock()` |
| `q-<n>` | 单选题题干 / 匹配项文本 | `renderChoiceGroup` / `renderMatchGroup` |
| `opt-<n>-<K>` | 单选选项 | `renderChoiceGroup` |
| `mopt-<from>-<K>` | 多选选项 | `renderMultiGroup` |
| `gh-<from>-<idx>` | 填空小标题（`type:'h'`） | `renderGapGroup` |
| `gl-<from>-<idx>` | 填空行（`type:'line'`） | `renderGapGroup` |
| `gt-<from>-<ri>-<ci>` | 表格单元格 | `renderGapGroup` |
| `gc-<from>-<idx>` | 表格 caption | `renderGapGroup` |

> `gt-` 前缀同时用于「组标题」（2 段）和「表格单元格」（4 段），段数不同，不会冲突。
> `start/end` 是**渲染文本**中的偏移：填空行里的 `{{n}}` 占位符不算字符（`fillGaps` 累加 `pos` 时跳过它），
> 也就是学生看到的纯文字（不含输入框）里的位置。没有占位符的块（题干 / 选项 / 说明）里，它与原始文本一致。
> 渲染时用 `paintQSeg(text, base, qrecs(key))` 按这个坐标系切段。

### 6.5 同义替换连线（双端）

一条连线在**两边各存一份**，`id` 相同：

```js
// T.custom[secId]
{ id:'lk-abc', cat:'link', p:17, s:135, e:139, q:null, note:'订房',
  qk:'q-1', qs:0, qe:6, qa:'Adelphi', bt:0.5 }
// T.qhl[secId]
{ id:'lk-abc', key:'q-1', start:0, end:6, type:'link', note:'订房', quote:'Adelphi' }
```

- 建立：`startLinkPick(sel)` → 在题目里拖选 → `openLinkBubbleForDraft()` → `saveLinkBubble()` 同时写两份。
- 反向：先在题目划词点「⟷ 替换」→ `linkFromQ` → 再在文稿划词。
- 改释义：`saveLinkBubble()` 同时更新 `m.note` 与 `r.note`。
- 删除：`deleteLinkBubbleMark()` 两边一起删。
- 撤销文稿时，用 `rebuildLinkQhl(s)` 按 `T.custom` 里的 link 重建题目端记录；题目上老师自己加的高亮 / Note 保留（不要整份覆盖）。
- 画线：`drawLinks()` 量两端 `getBoundingClientRect()`，三次贝塞尔，`x1 = 文稿 mark 右边`、`x2 = 题目 mark 左边`。泡泡默认放在两栏之间的空隙（`#trPane` 右边缘对应的曲线位置），位置存 `bt`。
- 窗口滚动 / resize / 重渲染后都要重画；现有实现用 `document` 的 scroll 捕获 + `requestAnimationFrame(drawLinks)`。

### 6.6 撤销 / 重做

| 栈 | 快照内容 | 触发 |
| --- | --- | --- |
| `markUndo[secId]` | `{ marks, qhl }` 深拷贝 | 所有文稿标注增删改、连线、拖动泡泡 |
| `ansUndo[secId]` | `{ answers, qhl }` 深拷贝 | 作答、题目标注、清空答案 |

- `pushMarkUndo()` / `pushAnsUndo(n, coalesce)` 在**改之前**压栈。
- `ansUndo` 支持合并：同一题 900ms 内的连续输入只存一次快照（`lastAnsEdit`）。
- Ctrl+Z / Ctrl+Y 按 `lastEditArea` 分发到 `undoMarks()` 或 `undoAnswers()`。
- 文稿撤销只回滚文稿，不误伤题目的高亮 / Note —— 靠 `rebuildLinkQhl`。

## 7. 题目渲染

### 7.1 四种 `kind` 的 DOM 契约

| kind | 外层 | 关键类 / 属性 | 作答控件 |
| --- | --- | --- | --- |
| `gap` | `.q-group[data-kind=gap]` | `.gap-line` / `.gap-table` / `.gap-h`，`data-qk` + `data-gap="1"` | `.gap-cell > input.gap-in[data-q]` |
| `choice` | `.q-group[data-kind=choice]` | `.q[data-q]`、`.q-text[data-qk=q-n]`、`.opt[data-val]` | `.dot[data-pick="1"]`（只有它能选） |
| `multi` | `.q-group[data-kind=multi][data-pick]` | `.opt.multi[data-val]`、`.opt-text[data-qk=mopt-*]`、`.multi-head`（已选 n/N） | `.box[data-pick="1"]` 方框 |
| `match` | `.q-group[data-kind=match]` | 普通匹配：`.q.match-q[data-q]`、`.slot[data-slot]`、`.opt-card[data-opt]` / `.letter-opt`；地图：`.map-group`、`.mg-table`、`.mg-dot[data-map-pick]` | 先点 `.slot` 激活，再点选项卡片（或拖拽）；地图点圆点 |

**作答只认圆点 / 方框**：`#qPane` 的 click 处理器先判断 `e.target.closest('[data-pick]')`，点到文字只当划词，不会改答案。新增题型时必须沿用这个规则。

匹配题另外有一条「先选槽位、再点选项」的路径：点 `.slot` 把它设为 `activeSlot`（已填则清空），随后点选项卡片会填进当前槽位并自动跳到下一个空槽。圆点 / 方框 / 槽位之外的点击都只用于划词。

### 7.2 填空占位符

- 数据里的题干 / 表格 / 行文本用 `{{n}}` 表示第 n 题的空。
- `fillGaps(text, key)` 把文本切成「纯文本段 + 空 + 纯文本段」，纯文本段用 `paintQSeg` 上色，空用 `gapInput(n)` 生成。
- 空的位置会影响 `qhl` 偏移：`paintQSeg` 的 `base` 是**已经走过的原始文本长度**（含 `{{n}}` 的 5 个字符），所以批注坐标以原始文本为准。
- 答案宽度：`gapWidth(v)` 按字数估算，输入时实时改 `input.style.width`，不重渲染。

### 7.3 答案与揭晓

- `answerInfo(n)` 按 kind 取答案文本：
  - `gap`：`g.answers[n]`，`a[]` 是可接受答案列表，`raw` 是展示写法；
  - `choice` / `match`：`items[].a` + 选项文本；
  - `multi`：`g.a` 字母数组，按 `from + i` 映射题号。
- `isRevealed(n)` 决定绿色答案是否显示；「答」按钮只改 DOM class，状态在内存里（不持久化，刷新后全部收起）。
- 题目工具条（`.q-tools`）只有三个入口：保存、题目笔记、清空所有笔记。`clearAnswers()` / `undoAnswers()` 仍保留在代码里，但当前没有「清空答案」的界面入口。

### 7.4 跳转定位

`jumpToAnswer(n)` 四级回退找答案句：
1. `#trBody mark[data-ids]` 里带该题 q 的标记；
2. `mark.mk[data-p][data-s][data-e]` 精确坐标；
3. 同坐标的 `.blank`；
4. 该题在 `T.custom` 里第一个标记所在段落 `.tr-para[data-p]`。

找到后 `scrollIntoView({behavior:'smooth', block:'center'})`，300ms 后兜底硬跳，加 `jumpPulse` 黄色描边动画。
入口：点填空空格、点题号、点数字条。地图题点 `.mg-dot` 也走这里。

### 7.5 配图

- `figKeyOf(g, s) = secId + '|' + g.from`。
- 优先级：`T.figs` 里**存在该 key**（包括空串）→ 用它；否则用数据里的 `g.figure`。空串 = 老师显式移除了图。
- `shrinkImageFile(file, maxW=1500)`：等比缩到最长边 1500，白底，WebP 0.92。
- 入口：拖拽 / 粘贴 / 点击上传 / 「替换 / 移除 / 放大」。改完 `persist()`。
- 判断「这组是否需要图」：`needFigure(g)` 看图或 instruction 里有没有 `label the map/plan/diagram`。

## 8. 富文本笔记

- 存储：`T.notes[secId]` 是**一段 HTML**，直接 `innerHTML` 回填；面板关闭时也会保存。
- 保存时机：输入后 500ms 防抖 `rtSaveSoon()`；切篇 `rtBeforeSwitch()`、导出前 `rtSaveNow()` 强制落盘。
- 工具栏：`document.execCommand`。两个坑：
  1. 字号要 `styleWithCSS=false` + `execCommand('fontSize', false, '7')`，再把 `<font size=7>` 转成 `<span style="font-size:Npx">`；
  2. 颜色 / 高亮要 `styleWithCSS=true`。
- 选区：点工具栏会丢选区，用 `rtRememberSel()` 缓存 `Range`，执行前 `rtRestoreSel()`。
- 粘贴：清洗成允许的标签（`p/br/b/strong/i/em/u/s/ul/ol/li/blockquote/pre/span[style]`），去掉脚本、class、外部图片（或转 base64，视需要）。
- 面板位置 / 大小 / 全屏存 `T.notesUI`；全屏切换要**先写状态再 toggle class**，否则读到旧值。
- 键盘：焦点在编辑器内时，除 `Esc` 和 `Ctrl/Cmd+S` 外全部 `return`，不要触发 T / 方向键快捷键。

题目侧还有两套轻量批注：
- `qhl` 里 `type:'note'` 的记录（`#qHlToolbar` 的 Note）→ `questionNoteList()` → `#notesPanelQ` 面板；
- `qhl` 里 `type:'hl'` 的高亮（可叠多层，深色表示 2 层以上）。

## 9. 投影 / 演讲者视图

### 9.1 结构

`openProjection()`：

1. `window.open('', '_blank')`，尽量 `placeProjectionOnOtherScreen()` 移到第二块屏；
2. `w.document.write(projDocHTML())` —— **不是 iframe**，是完整新文档；
3. 主窗口持有 `projWin`，新窗口通过 `window.opener.__projXxx()` 反向调用。

`projDocHTML()` 会把主文档所有 `<style>` 拼进去，所以新增样式自动同步；但 `body` 上加 `class="proj"` 覆盖布局（`.proj-main/.proj-tr/.proj-drag/.proj-q`）。

### 9.2 同步协议（opener 暴露的方法）

| 方法 | 作用 |
| --- | --- |
| `__projToggleTr()` | 投影显示 / 隐藏文稿 |
| `__projFont(delta)` | 改字号（同步 `T.fs` 并 `applyFont()`） |
| `__projSetSplit(pct)` | 拖分隔条改左栏宽度 |
| `__projSaveSplit()` | 拖完落盘 |
| `__projScrollFrom(which, ratio)` | 投影滚动 → 主窗口按比例跟随 |
| `__projRedraw()` | 重画投影里的连线 / 笔记位置 |

主 → 投影：`syncProjection()` 重写 `#projQ` / `#projTr` 的 HTML、应用字号主题、同步笔记与连线。

### 9.3 三个必须知道的坑

1. **后台窗口的 `requestAnimationFrame` 会被节流**，投影窗口没聚焦时滚动同步会卡。所以滚动同步是「scroll 事件里直接算」，不要依赖 rAF。
2. **双向滚动回声**：用 `projScrollGuard` / `__syncLock` + 160ms 时间窗，收到同步事件时不要再回传。
3. **笔记面板位置**：两个窗口尺寸不同，用**屏幕坐标百分比**（`projPlaceBox`）映射，不要直接复制 px。

## 10. 导出 PDF

两个构建函数，共用同一份 `printTranscript` / `printQuestions`：

| 函数 | 版式 | 说明 |
| --- | --- | --- |
| `buildWebPrintHTML(o)` | 网页版（默认） | 左文稿 44% / 中缝 12% / 右题目 44%，超长单页，画连线与泡泡 |
| `buildPrintHTML(o)` | A4 单栏 | 自动分页，适合打印到纸，不含连线 |

选项对象：`{ transcript, questions, notes, answers }`（`answers` = 是否额外打印参考答案；学生已填答案始终打印）。

### 10.1 网页版的关键实现

1. **端点标记**：`printTranscript` 给片段加 `data-lk="id1 id2"`（取该片段覆盖的所有 link），`printQSeg` 同理，并加 `.p-qlink`。
   > 不能只看「最高优先级是不是 link」，否则被 note / underline 盖住时端点会丢。
2. **打印页自带布局脚本** `__pLayout()`：
   - 量 `#pwLeft [data-lk~=id]` 最右矩形 与 `#pwRight …` 最左矩形；
   - 画三次贝塞尔（控制点水平外扩 `dx = max(26, |x2-x1| * 0.42)`）；
   - 泡泡按 `m.bt` 或中缝中心定位，重叠时上移，夹在栏顶 / 页底之间；
   - 最后设 `@page{size:210mm <实测高度>mm;margin:0}`，把整篇变成一张超长页。
3. **打印页里的 `<script>` 必须写成 `\x3Cscript` / `\x3C/script`**，否则会提前结束主文档的 script 块。
4. **`#pBubbles` 必须 `width:100%`**。绝对定位容器的宽度决定子元素 shrink-to-fit 的可用宽度；为 0 时中文泡泡会一字一行。
5. **泡泡不要 `box-shadow`**，Chrome 打 PDF 时会渲染成灰色方块。
6. **说话人 `.p-spk` 用 `inline-block`**，`display:block` 会让每段多一行，整页高 100mm+。
7. 页面高度在 `load`、`beforeprint` 和 opener 调用时各算一次，防止图片解码晚于首次布局。

### 10.2 新增导出内容时的检查表

- [ ] 两个 builder 都改了吗？（否则两种版式不一致）
- [ ] 新增的 HTML 片段在打印页里没有 `</script>` 字面量？
- [ ] 颜色有 `print-color-adjust: exact`？
- [ ] 需要跨页不断开的内容加了 `break-inside: avoid`？
- [ ] A4 版页数是否仍然合理？（用第 11 节的方法验证）

### 11.1 设计 token

| Token | 浅色 | 深色 | 高对比 |
| --- | --- | --- | --- |
| `--bg` | `#eef0f3` | `#211e1d` | `#000` |
| `--panel` | `#fff` | `#2a2624` | `#000` |
| `--ink` | `#171a1f` | `#ede6dd` | `#ffe600` |
| `--ink-2` | `#5b636d` | `#b8aea3` | `#ffe600` |
| `--accent` | `#1a4fd6` | `#d8b26a` | `#ffe600` |
| `--line` | `#dfe3e8` | `#463f39` | `#4a4400` |
| `--m-answer` | `#1f8a5f` | `#7fd3a8` | `#7dff9e` |
| `--m-distract` | `#c0392b` | `#f08a7c` | `#ff8a80` |
| `--m-link` | `#db2777` | `#f472b6` | `#ff79c6` |
| `--m-underline` | `#7c3aed` | `#a78bfa` | `#d8b4fe` |

- **字号唯一入口** `--fs`（15–26）。所有尺寸用 `calc(var(--fs) * 比例)`：
  - 顶栏文字 `.55–.8`，正文 `1`，辅助 `.44–.62`。
  - 面板标题 `.75–.9`；标注泡泡 `.62`。
- 圆角：按钮 7px、卡片 10–14px、标注 2–3px、泡泡 9px。
- 阴影：`--shadow`（浅色柔和、深色更重、高对比无阴影）。
- 过渡：`.15s`，只过渡颜色 / 边框 / 阴影，不做位移动画（课堂投影卡顿明显）。

### 11.2 布局

- 顶栏固定 56px；`.main` 横向 flex；`#trPane` 默认 52%（`T.proj.split`），`#dragbar` 8px。
- 文稿隐藏时 `.tr-hidden` 占满左栏，不是 `display:none`（保留分栏宽度记忆）。
- 说话人列宽 `--spk-w` 由 `fitSpeakerCol()` 按本篇最长标签实测设置（70–160px），`.tr-spk` 用 `nowrap`；改名 / 改字号 / 切篇后都会重算，避免 `LIBRARIAN`、`PRESENTER` 这类长名折行。
- 投影窗口：`.proj-tr` 用 `--proj-trw`，`body.tr-off` 隐藏。
- 窄屏（<1100px）不保证可用；这是桌面 / 投影工具。

### 11.3 交互与可访问性

- 所有图标按钮有 `title`；状态用 `aria-pressed` / `aria-checked`。
- 可点击元素最小 30×30；只有圆点 / 方框可作答。
- `Esc` 关闭浮层 / 退出划词模式；`kbd` 样式统一。
- toast 2.2s 自动消失，同一时刻只显示一条。
- 中文文案用「你」，不用「您」；句子短，避免术语。

### 11.4 打印样式

- 打印页背景一律浅色（深色主题不带到 PDF）。
- 彩色标记必须 `print-color-adjust: exact`。
- `@page` 宽固定 210mm；网页版高度动态。
- 表格 `border-collapse` + 细线 `0.22mm`，不要用 `1px` 在 PDF 里发虚。

## 12. 代码约定

| 约定 | 说明 |
| --- | --- |
| 转义 | 所有插入 HTML 的文本走 `esc()`（主文档）或 `pEsc()`（打印页）；不要拼裸字符串 |
| 命名 | 渲染 `renderXxx`、刷新 `refreshXxx`、开关 `openXxx/closeXxx`、取数 `xxxOf` |
| 事件 | 委托绑在稳定容器；`pointerdown/move/up` 用于拖拽（同时兼容触屏） |
| 状态 | 先改 `T`，再 `persist()`，再 `render`；不要反过来 |
| 深拷贝 | 快照 / 基线用 `clone(obj)`（JSON 深拷贝，数据必须可序列化） |
| 注释 | 中文；解释「为什么」而不是「做了什么」，尤其是兼容性 workaround |
| 依赖 | 不新增；确需引入先讨论 |
| 格式 | 2 空格缩进、单引号、行尾分号；单行控制在 ~120 字符 |

**禁止**

- 在渲染出来的节点上绑事件（会被下一次 `innerHTML` 干掉）。
- 直接改 `DEFAULTS`（它是新标注的来源，改了会污染未编辑过的篇目）。
- 在 `T` 里塞 DOM 节点、函数、循环引用（`persist` 会炸）。
- 在 `#data` 里写注释（必须是合法 JSON）。
- 在打印 HTML 的模板字符串里写裸 `<script>`。

## 15. 已知坑（都是踩过的）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 主脚本整段失效、白屏 | 模板字符串里出现 `</script>` | 写成 `\x3C/script` |
| PDF 里泡泡一字一行 | 绝对定位容器宽度 0 | 容器 `width:100%` |
| PDF 泡泡带灰方块 | `box-shadow` 被光栅化成硬阴影 | 打印样式去掉 shadow |
| 投影滚动不同步 | 后台窗口 rAF 被节流 | scroll 事件里直接同步，不用 rAF |
| 滚动两边互抖 | 双向 scroll 回声 | guard + 160ms 锁 |
| 重渲染后输入框值没了 | `innerHTML` 不保留 `input.value` | 渲染时 `value="…"`，或干脆不整体重渲染 |
| 撤销把题目高亮也回滚了 | 快照包含整份 `qhl` | 文稿撤销后用 `rebuildLinkQhl` 重建，不覆盖题目自建记录 |
| 笔记字号设了没反应 | `execCommand('fontSize')` 只认 1–7 | `styleWithCSS=false` + 7 再转 px |
| 全屏笔记位置错乱 | 切换前读了旧 `T.notesUI` | 先写状态再 toggle class |
| 打字时按 T 跳去显示文稿 | 全局快捷键没排除编辑器焦点 | 编辑器内除 Esc / Ctrl+S 全部 return |
| 新标注被旧缓存盖住 | `localStorage` 里有旧 baseline | 改 `DATA_VER` |
| 存储写满、改动丢失 | 图片太多超过 5MB | 压图、提示导出 PDF |
| 打印页高度不够 / 被裁 | 图片加载晚于首次布局 | `load` + `beforeprint` 各重算一次 |
| Safari 打印分页怪 | 自定义 `@page` 支持差异 | 建议 Chrome / Edge 导出 |

## 16. 性能与容量

- 单节 33–69 段、10 题量级，全量 `innerHTML` 重建在 10ms 内，**不需要虚拟 DOM**。
- 真正的开销在 `drawLinks()`：每次滚动都重画所有曲线。连线超过 ~30 条时考虑只画视口内的（现有实现已跳过视口外的端点）。
- 配图是大头：一张 1500px WebP ≈ 60–150KB，base64 后 ≈ 80–200KB。`localStorage` 5MB 大约放 20–30 张图。
- 富文本笔记里的图片最容易撑爆存储，粘贴前提示压缩或改用文字。

## 17. 明确没做的（避免重复提需求）

- 音频播放 / 听写时间轴（当前只有文本）。
- 云端同步、账号、多人协作（定位是本机工具）。
- 移动端 / 平板适配（投影与桌面为主）。
- 题库编辑器 UI（改数据走 JSON + 校验脚本）。
- 导出 Word / 图片。
- 自动批改（答案揭晓是给老师看的，不做判分）。
